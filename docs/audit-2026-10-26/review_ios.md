## 3. UNCERTAIN (not reported as defects)

- Duplicate payment sheet binding: `showPaymentMethodsSheet` is bound to a `.sheet` both in RideBottomSheet (RideRequestView.swift:760-764, new) and RideStatusCard (:2344-2348), and RideStatusCard lives inside `.fullScreenCover(isPresented: $viewModel.isRideActive)` (:153) over RideBottomSheet. If SwiftUI fires `onDismiss` for both, `retryAcceptBidAfterPaymentSetup()` runs twice; the second pass skips `bidPendingPaymentSetup` (already nil) and hits the `else if pickupAddress != nil` branch (RideRequestViewModel.swift:719-722) which calls `retryRequestRide()` and could create a duplicate ride request during an active ride. Need a device run (accept bid with no saved card while the cover is up) to confirm only one onDismiss fires.
- `completeMatch(with:)` (RideRequestViewModel.swift:661-681, new counter-offer path) builds `AcceptedDriverInfo` with `license_plate: nil`, `vehicle_color: nil`, `phone: nil` (same as the normal path, which can be replaced by `response.driver`). Phone is back-filled by tracking (:936-953) but plate/color are not; need to check whether the UI needs them (safety: rider matching plate) and whether the tracking response carries them.
- "Driver earned" on the rider receipt (RideRequestView.swift:2500) = `fareBeforeTax - platformFee - regulatoryFee`. Backend splits CPUC Access-for-All 0.05 rider/0.05 driver (pricing_config.py:47-49), so subtracting the rider-side `regulatoryFee` equals the driver share only while the two shares are equal; and it differs from `viewModel.driverEarnings` (fare minus driverPlatformFee, no AFA). Verify against the server `driver_payout`.
- Driver `SubmitBidSheet.isValidBid` (:34) only requires price > fee; no ceiling. Whether the server rejects absurd bids (e.g. 99999) was not checked.
- Privacy manifests: both declare required-reason categories SystemBootTime (35F9.1) and DiskSpace (E174.1) and FileTimestamp, but I found no app-code use (third-party SDKs may use them, which ship their own manifests). Customer declares DeviceID/Analytics (unlinked) though no analytics SDK is in the project (possibly FCM token). Driver: no declaration for the audio/speech data sent to Apple by `SFSpeechRecognizer` (`requiresOnDeviceRecognition = false`, VoiceAssistantManager.swift:164) and nothing for financial/earnings data or ID documents beyond OtherUserContent/Photos. Needs the App Store Connect nutrition label compared side by side.
- Driver pbxproj switches 4 target configs to `CODE_SIGN_STYLE = Manual` and the app configs to hardcoded profile UUIDs (delivery project.pbxproj; customer uses a UUID specifier too). Fine if intended for CI/export, but archives on another machine fail without those profiles. Not a code defect.
- ISO8601 parsing in driver `elapsedSecondsSinceArrival` (ActiveRideView.swift:827-830, unchanged) requires fractional seconds and a zone; the new receipt parser comment (RideReceiptView.swift:632) states the server sends naive UTC with microseconds, so the driver's no-show timer may fall back to the full wait window. Unchanged code, not verified against the real `driver_arrived_at` format.
