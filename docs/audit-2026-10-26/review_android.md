## 3. UNCERTAIN (not confirmed by reading code alone)

1. **Payments policy for founding membership** (app and driver `FoundingMemberScreen`, driver FoundingViewModel.kt:15). Both apps collect a $100 non-refundable "lifetime fee-lock" by card inside the app. Whether Play treats this as a digital-goods purchase needing Play Billing, and whether the server enforces "fees locked for life" while the loader now allows changing fees for everyone, I could not verify. Check the backend fee logic and your Play Payments policy position. The driver flow tokenizes the card and the server charges a `payment_method_id`; I could not see 3-D Secure handling for cards that require authentication.
2. **Phone masking** (DriverPrivacyScreens.kt:278, HelpSupportScreen.kt:101). Confirm whether the `customer_phone` the server returns is a relay number. If it is a real number, finding 11 stands as a deceptive privacy claim.
3. **Background-check and monitoring claims** (DriverPrivacyScreens.kt:424-435). The project memory says Checkr gate enforcement is still pending. Verify the backend before shipping "All drivers undergo background checks".
4. **Rejected-bid label** (RideshareModels.kt:41-48). A bid the driver rejected through `rejectCounter` may come back as `rejected` with an open ride and show "Declined by rider". Check the server status values.
5. **Access-for-All derivation** (ActiveRideViews.kt:370-371). The deduction is inferred from `fare + tip - fee - payout`. Other payout adjustments (no-show) would be mislabeled. Check the backend payout formula.
6. **Map camera fit** (ActiveRideViews.kt:113-117). `newLatLngBounds` without a map size can throw `IllegalStateException` before layout. It is wrapped in `runCatching`, so the effect is only that the camera may never fit both points. Needs a device check.
7. **java.time on API 24-25** (ActiveRideViews.kt:42-44, 78-84; CustomerRideshareApiService `ReceiptEnvelope.formatUtc`). minSdk is 24 and a grep of the gradle files finds no core-library desugaring. All use sites are inside `runCatching`, which fails safe (no-show timer never unlocks, raw timestamp shown) on Android 7.x. Confirm desugaring is enabled in the app/driver gradle files.
8. **Receipt payment label** (CustomerRideshareApiService.kt `toReceipt`). Anything that is not "demo" is labeled "Card", including `pending`, `failed` and `refunded` statuses. Confirm the backend status values.
9. **Fare breakdown versus total** (RideRequestScreen.kt:665-681). Base + distance + time rows are shown, but `MINIMUM_FARE` (now 8.00 on both sides) is applied only in the total, so the rows may not add up for short rides.
10. **Chat `sender_type`** (DollorRepository `sendDriverRideChat` posts `"driver"`). A client-supplied sender role; confirm the server derives it from the token.
11. **Disability data** (accessibility notes sent to drivers). Sensitive data, with no explicit consent text next to the toggle. The privacy policy only says "limited trip information". Review against the Play data-safety form.
12. **Driver location while backgrounded**. Background location and the foreground-service permissions were correctly removed and the rationale text is truthful ("while online and the app is open"). The driver stays "online" server-side when the app is backgrounded, so riders may be matched on stale location. Product decision.
13. **Inverted legacy color names** (app/ui/theme/Color.kt:22-25: `BrandBlack = white`, `white = #17171A`). Not a defect today. Any code that uses the `white` or `black` names expecting real white or black will invert.
14. **Debug logging in release**. `HttpLoggingInterceptor` is set to BASIC in debuggable builds and NONE otherwise. `ApiTiming` logs only method, path, status and time. Both are acceptable, and the ApiTiming design avoids logging headers or bodies. The `CustomerRideshareApiService` private OkHttp client has only `ApiTiming`, so no body logging was introduced.
